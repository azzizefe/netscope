## 1. Adım: Git Depo Geçmişinin Arındırılması (Güvenlik & Lisans)
Npcap SDK ikililerinin (`Packet.lib`, `wpcap.lib`) ticari lisans gereksinimleri nedeniyle deponun Git geçmişinde bulunması yasal risk oluşturur. Ayrıca geçmişteki build çıktıları (.exe, .zip, .msi) `.git/` boyutunu şişirmektedir.

- [ ] **1.1. Deponun yedeğini alın (Yıkıcı işlem öncesi önlem):**
  ```bash
  git clone --mirror . ../netscope-history-backup.git
  ```
- [ ] **1.2. filter-repo ile lisanssız ve büyük dosyaları tamamen geçmişten silin:**
  ```bash
  git filter-repo --invert-paths \
    --path npcap-sdk \
    --path dist/windows/netscope.exe \
    --path dist/windows/netscope_0.1.0_x64-setup.exe \
    --path dist/windows/netscope_0.1.0_x64_en-US.msi \
    --path dist/netscope-windows-v0.1.0-x64.zip
  ```
- [ ] **1.3. Uzak depoyu (remote) tekrar bağlayın ve force-push yapın:**
  ```bash
  git remote add origin https://github.com/azzizefe/netscope.git
  git push --force --all origin
  git push --force --tags origin
  ```
- [ ] **1.4. Doğrulama:** Aşağıdaki komutların çıktıları boş dönmelidir:
  ```bash
  git log --all --oneline -- npcap-sdk
  git rev-list --objects --all | grep -iE "\.(exe|msi|zip)$"
  ```

## 2. Adım: Çoklu Platform Güvenlik Duvarı Bloklama (OS Integration) — ✅ TAMAMLANDI (2026-08-02)
IP engelleme özelliği şu anda yalnızca Windows üzerinde `netsh` komutlarıyla çalışmaktadır. Linux ve macOS sistemler için gerçek güvenlik duvarı backend'leri yazılmalıdır.

> **Durum:** `crates/core/src/firewall.rs` artık üç platformu da kapsıyor ve
> `is_supported()` üçünde de `true` dönüyor (`support_flag_matches_platform`
> testi bunu sabitliyor). **Tek sapma:** Linux tarafı `nftables` yerine
> `iptables`/`ip6tables` kullanıyor. Modern dağıtımlarda `iptables` zaten
> nft-destekli bir uyumluluk katmanıdır, ama yalnızca `nft` kurulu bir hostta
> engelleme başarısız olur. Gerçek bir `nft` backend'i isteniyorsa ayrı bir iş
> kalemi olarak açılmalı.

- [x] **2.1. Linux backend'ini yazın:** *(iptables/ip6tables olarak yapıldı)*
  [firewall.rs](file:///c:/Users/efe/Desktop/netscope/crates/core/src/firewall.rs) içerisindeki `cfg(not(windows))` modülüne `nftables` desteği ekleyin. Linux üzerinde root yetkileriyle şu kurallar eklenmeli ve silinmelidir:
  ```bash
  # İlk başlatmada tablo ve zincir oluşturma:
  nft add table inet netscope
  nft add chain inet netscope filter { type filter hook input priority filter \; policy accept \; }
  
  # Kural ekleme (Block):
  nft add rule inet netscope filter ip saddr <ip> drop
  
  # Kural silme (Unblock):
  # Kuralın handle ID'sini bulup silmek veya tabloyu tamamen temizlemek:
  nft flush table inet netscope
  ```
- [x] **2.2. macOS `pfctl` (Packet Filter) Backend'ini yazın:**
  [firewall.rs](file:///c:/Users/efe/Desktop/netscope/crates/core/src/firewall.rs) içerisine macOS pfctl anchor'larını manipüle edecek yapıyı kurun:
  ```bash
  # Kural ekleme:
  echo "block drop from <ip> to any" | pfctl -a netscope -f -
  
  # Aktifleştirme:
  pfctl -e
  ```
- [x] **2.3. Platform destek flag'lerini güncelleyin:**
  [firewall.rs](file:///c:/Users/efe/Desktop/netscope/crates/core/src/firewall.rs) altındaki `is_supported()` fonksiyonunu Windows, Linux ve macOS için `true` dönecek şekilde güncelleyin.
- [x] **2.4. Test edin:**
  ```bash
  cargo test -p netscope-core --lib support_flag_matches_platform
  ```
